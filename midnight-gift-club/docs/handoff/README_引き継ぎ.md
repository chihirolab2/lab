# MIDNIGHT GIFT CLUB — デザイン・実装引き継ぎ

## 1. プロジェクト概要
恋人・好きな人と「一緒にしたいこと」をチケットとして贈り合う、2人用のデジタルチケットブック。贈り主が用意したチケットを使うだけでなく、受け取る側もアプリ内フォームからリクエストを送り、採用された内容が新しいチケットとして追加される。チケットを使うとスタンプが貯まり、10個でプレミアムチケットを獲得する。

## 2. デザイン方針（現時点の合意）
- コンセプト：Midnight Luxury × playful vintage ticket stationery
- 全体の印象：大人っぽさ7：遊び心3。34歳男性が日常的に使っても甘すぎない。
- HOME：ギフトボックスを主役に。夜景・星・柔らかい光の粒・リボンを使用。
- アプリの基本背景：ミッドナイトネイビーとアイボリーを使い分ける。
- アクセント：シャンパンゴールド。
- チケット：種類ごとに色とデザインを変える。参考画像のような横長の紙チケット、ストライプ縁、ミシン目、バーコード、シリアル番号。
- フォント：日本語は読みやすいサンセリフ（Noto Sans JP等）。英字は太めで個性のあるディスプレイ系。明朝体をUI全体の基本にしない。筆記体はロゴや短いアクセントだけ。
- 重要：装飾過多にせず、操作画面の可読性とタップしやすさを優先。

## 4. 画面構成
1. HOME：ギフトボックス、ウェルカムメッセージ、所持チケットへの導線、スタンプ進捗、新着リクエスト通知。
2. TICKETS：未使用／使用済み／プレミアムの一覧。横長チケットカードを表示。
3. TICKET DETAIL：チケットの大きなビジュアル、説明、有効期限・利用条件、使用ボタン。
4. REQUEST：相手が「一緒にしたいこと／してほしいこと」をアプリ内フォームから送信。カテゴリ、内容、任意メモ。
5. REQUEST INBOX：新着通知、リクエスト詳細、採用／保留／見送り。
6. STAMP：初期状態0/10。チケットを1回使用するごとに1スタンプ。
7. PREMIUM：10個達成時にプレミアムチケットを付与する特別演出と詳細。
8. HISTORY：使用済みチケットと過去のリクエストを確認。

## 5. チケットの初期カテゴリ案

## 6. 機能仕様
### チケット
- 贈り主がチケットを作成・編集・追加できる。
- 受け取り側からのリクエストを採用した場合もチケットとして追加できる。
- チケットは未使用／使用済みで管理する。
- 使用済みチケットの二重使用を防止する。
- 使用時に確認ダイアログを表示する。

### リクエスト
- 受け取り側がアプリ内フォームからリクエストを送る。
- 状態：PENDING（受付）／ACCEPTED（採用）／ON_HOLD（保留）／DECLINED（見送り）／COMPLETED（チケット使用済み）。
- 採用時、贈り主がチケット名・説明・カテゴリ・色・期限などを整えて追加する。
- 新着リクエストはアプリ内通知に表示。Web Pushは後続対応（許可取得・配信基盤が必要）。

### スタンプ／特典
- 初期スタンプは0個。最初から10個埋めない。
- 通常チケットを1回使用するごとに1個付与。
- 10個達成時にプレミアムチケットを1枚自動発行。
- 達成後は次のカードを0/10で開始。
- プレミアムチケット使用時のスタンプ付与は要確認。現時点では通常チケットの使用を基本対象とする案。

## 7. 推奨ナビゲーション
下部タブ4つ：HOME / TICKETS / REQUEST / STAMP。
通知はヘッダーのベルまたはHOMEの通知カードから確認。MY PAGE・HISTORYはメニュー内でもよい。

## 8. データモデル案
- users：id, display_name, role, avatar_url
- tickets：id, title, category, description, color_theme, image_url, serial_no, status, expiry_date, terms, created_by, created_at, used_at, is_premium, source_request_id
- requests：id, sender_id, category, title, message, preferred_place, status, created_at, reviewed_at, resulting_ticket_id
- stamp_cards：id, owner_pair_id, current_count, target_count（10）, completed_at
- stamp_events：id, ticket_id, earned_at, card_id
- notifications：id, recipient_id, type, title, body, related_id, read_at, created_at

## 9. 実装上の注意
- 2人の端末で状態を同期するには、共有バックエンドと認証が必要。ローカルストレージだけでは相手端末に通知・同期できない。
- 最初はUIプロトタイプをモックデータで実装し、その後バックエンド・招待リンク・認証・通知を追加する段階的開発を推奨。
- 実際の画像素材はこのフォルダのムードボードを方向性資料として参照。画像生成ボード内の文字や小さなUIは崩れることがあるため、そのまま切り出して本番UIに使わず、CSS/HTMLで再構築する。
- チケットのバーコードは現時点では装飾。実際の検証用途に使う場合は一意のIDとサーバー側検証を実装する。
